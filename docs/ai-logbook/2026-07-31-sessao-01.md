## Onde a IA errou

| #   | Sintoma                                  | Causa raiz                                  | Como identifiquei       | Correção                         |
| --- | ---------------------------------------- | ------------------------------------------- | ----------------------- | -------------------------------- |
| 1   | `npm install` falhou com `ETARGET`       | Versão `@eslint/js@^10.8.0` não existe      | `npm install` abortou   | Fixado `^10.0.1`                 |
| 2   | `tsc`: _"not callable"_ em `pino-http`   | Import `default` de pacote CommonJS sob ESM | `npm run typecheck`     | Import nomeado `{ pinoHttp }`    |
| 3   | `/health` respondia `200 OK`, mas errado | Porta 3333 ocupada por outro projeto meu    | Campo `service` no JSON | API movida para a porta **4000** |

**Detalhe #1 — versão inexistente.** `npm install` abortou com
`ETARGET — No matching version found for @eslint/js@^10.8.0`. A IA assumiu que o
`@eslint/js` acompanharia a numeração do `eslint` (10.8.0), mas a versão real era 10.0.1.
Corrigido consultando `npm view @eslint/js version` antes de confiar em qualquer versão gerada.

**Detalhe #2 — import errado sob ESM.** O código gerado tinha
`import pinoHttp from 'pino-http'`. Sob ESM + `moduleResolution: NodeNext`, o `default` de um
pacote CommonJS é o `module.exports` inteiro, não a função exportada — o TypeScript recusou com
`TS2349: This expression is not callable`. Corrigido com o import nomeado:
`import { pinoHttp } from 'pino-http'`.

**Detalhe #3 — o mais instrutivo.** O navegador mostrava "API indisponível", mas um `curl`
direto no `/health` devolvia `200 OK`. A resposta vinha de **outro projeto meu**
(`portfoliolab-api`), que ocupava a porta 3333 desde 29/07 — a API do Circula sequer chegou a
subir sem erro visível. Um teste que verificasse só o status HTTP teria passado. O que
denunciou foi o campo `service` no corpo, que trazia `"portfoliolab-api"` em vez de
`"circula-api"`. Diagnostiquei com `Get-NetTCPConnection -LocalPort 3333` e movi o Circula para
a porta **4000**. Lição: **`200 OK` prova que alguém respondeu, não que foi o servidor certo.**

Vale registrar também um acerto por desconfiança: a versão mais recente do TypeScript no npm é
a **7.x**, mas o `typescript-eslint@8` declara peer dependency `>=4.8.4 <6.1.0`. Instalar a
mais nova quebraria o lint do monorepo inteiro. Fixei em `5.9.3`, sem `^`.

## O que aprendi

- **Workspaces do npm** criam link simbólico entre pacotes locais — é isso que faz
  `@circula/shared` funcionar sem publicar nada.
- **ESM exige extensão no import** (`./app.js` dentro de um `.ts`), porque o caminho precisa
  existir em tempo de execução.
- **Express 5** propaga erros de `async` sozinho, e identifica o error handler pela aridade de
  4 parâmetros — remover o `next` não usado quebra o middleware silenciosamente.
- **Modelo de linguagem não consulta o registro do npm.** Ele infere números de versão
  plausíveis. Validar com `npm view <pacote> version` virou passo obrigatório.
