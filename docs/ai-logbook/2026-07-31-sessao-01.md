## Onde a IA errou

| #   | Sintoma                                                                                | Causa raiz                                                                                                                                                    | Como identifiquei                                                             | Correção                                                                                   |
| --- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 1   | `npm install` abortou com `ETARGET — No matching version found for @eslint/js@^10.8.0` | A IA assumiu que o `@eslint/js` acompanha a numeração do `eslint` (10.8.0). A versão real é 10.0.1                                                            | O próprio `npm install` falhou                                                | `npm view @eslint/js version` e fixado `^10.0.1`                                           |
| 2   | `tsc` acusou `TS2349: This expression is not callable` em `pino-http`                  | `import pinoHttp from 'pino-http'`. Sob ESM + `NodeNext`, o `default` de um pacote CommonJS é o `module.exports` inteiro, não a função exportada              | `npm run typecheck`                                                           | `import { pinoHttp } from 'pino-http'`                                                     |
| 3   | O navegador mostrava "API indisponível", mas `curl` no `/health` devolvia `200 OK`     | A resposta vinha de **outro projeto meu** (`portfoliolab-api`) que ocupava a porta 3333 desde 29/07. A API do Circula logou "ouvindo na 3333" sem erro nenhum | O corpo do JSON trazia `"service":"portfoliolab-api"` em vez de `circula-api` | `Get-NetTCPConnection -LocalPort 3333` identificou o PID; Circula movido para a porta 4000 |

**O erro mais instrutivo foi o 3.** Um teste que verificasse só o status HTTP teria passado —
era `200 OK`. O que denunciou foi o campo `service` no corpo. Ficou a lição: **`200 OK` prova
que alguém respondeu, não que foi o servidor certo.** Por isso o `/health` do Circula devolve
`service` e `version`, e não apenas `{ "status": "ok" }`.

Vale registrar também um acerto por desconfiança: a versão mais recente do TypeScript no npm é
a **7.x**, mas o `typescript-eslint@8` declara peer dependency `>=4.8.4 <6.1.0`. Instalar a
mais nova quebraria o lint do monorepo inteiro. Fixei em `5.9.3`, sem `^`.

## O que aprendi

- **Workspaces do npm** criam link simbólico entre pacotes locais — é isso que faz
  `@circula/shared` funcionar sem publicar nada.
- **ESM exige extensão no import** (`./app.js` dentro de um `.ts`), porque o caminho precisa
  existir em tempo de execução.
- **Express 5** propaga erros de `async` sozinho, e identifica o error handler pela aridade de
  4 parâmetros — remover o `next` não usado quebra o middleware silenciosamente.
- **Modelo de linguagem não consulta o registro do npm.** Ele infere números de versão
  plausíveis. Validar com `npm view <pacote> version` virou passo obrigatório.
